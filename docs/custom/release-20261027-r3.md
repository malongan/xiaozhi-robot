# 2026-10-27 r3：插着充电器不再自动休眠（满电场景）

修复「插充电头、电池已充满时设备仍会进档 2 并自动深度休眠」的遗留问题。

**基线** `custom-final-20261027-r2` · **ESP-IDF** 6.1 · **组合** `media`

## 一、现象

把设备插在**纯充电头**（不接电脑的数据口）上，电池已经充满，几小时后设备照样进档 2
（屏幕全黑），再往后自动深度休眠，必须按 BOOT 才能唤醒。

插在电脑 USB 上不会出现这个问题，所以之前一直没暴露。

## 二、根因

外部供电判定原来只有三条判据，全部失效于「纯充电头 + 满电」这一种形态：

| 判据 | 为什么失效 |
|---|---|
| `usb_serial_jtag_is_connected()` | 纯充电头没有数据线枚举，读不到 |
| `!IsBatteryPresent()` | 电池装着，而且满电 |
| `IsCharging()`（电压阶跃 / 斜率） | 满电后 TP4054 停止灌电流，电压既不跳变也不上升 |

`IsCharging()` 本身靠两个动态特征推断：插拔瞬间的电压阶跃（±12 mV），以及 5 分钟基线
的斜率（±8 mV/5min）。满电时两个都是 0，状态停在默认的「未充电」。

## 三、为什么不能简单调阈值

原计划是加一条「电压 ≥ 4180 mV 就认为还插着电」。真机实测直接否掉了这个思路：

- 插在 USB 上、电池满电时，读数 **4170 mV**
- 同一时刻连续采样：`4170 → 4164 → 4170 → 4166`，**±6 mV 噪声**
- 拔线后的开路电压只比充电时低 **约 10 mV**

也就是说「插着」和「没插」的电压差，和 ADC 噪声是同一个量级。用任何固定阈值
（4180 会漏判充电头，4150 会把拔线的满电误判成插着）都不可靠。

## 四、方案：改成趋势判据

既然瞬时电压不可分，就看**长时间里到底在不在往下掉**：

> 电压 ≥ 4100 mV，并且 90 分钟内没有下滑趋势（≥10 mV），则认为仍接在外接电源上。

物理依据：接在充电头上时 TP4054 恒压把电池端电压顶住，纹丝不动；拔线后由电池供电，
开路电压会持续往下走，90 分钟内一定掉够 10 mV。

## 五、改动

- `FreenovePowerMonitor` 新增 `slow_history_`：每分钟一个采样点，保留 90 分钟。
  原来 2 秒一采的 `history_` 只有 12 分钟，撑不起这个观察窗口。
- 新增 `IsBatteryDeclining()`：取慢历史首尾各 3 点中位数比较，下滑 ≥10 mV 判为在放电。
- **`external_power_` 与 `charging_` 拆开**：满电后不再「充电」，但线还插着。省电逻辑要的是
  后者，UI 要的是前者（满电应显示充满，不是充电中）。
- 板级 `IsExternalPower()` 简化为直接转发给 monitor，四条判据集中在一处。

## 六、验证

编译后临时跳过「USB 主机」和「正在充电」两条判据，强制走新判据，真机日志确认命中：

```

```

```

I (1000) ... Idle power save: light=30s deep=7200s auto_sleep=14400s
```

固件 **3,914,592 B**，app 分区余量 37%，启动零异常。

## 七、代价与边界

- **拔线后最多 90 分钟才恢复省电**：这段时间不做档 2、不自动关机。属于安全侧延迟
  （省电暂时不生效），不会误休眠。用户拔线后有交互时本来也会重置 idle 计时。
- **刚开机前 3 分钟**慢历史不足，按「不下滑」处理，即乐观判为插着电。同样落在安全侧。
- 「拔线后电压下滑被正确识别」这一段需要实际使用观察，本次未做长时验证。
- CHRG 引脚仍未引到 GPIO，本质仍是电压推断；若以后飞线到 IO2/IO3/IO14/IO21，
  把引脚传给 `FreenovePowerMonitor` 构造参数即可切成硬件直读，这套启发式自动失效。
