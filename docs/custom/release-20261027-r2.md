# 2026-10-27 r2 版本说明：设置页调档导致重启的修复

本版是 [release-20261027](release-20261027.md) 的热修。功能不变，只修一个问题：
**在设置页调节「深度省电」「自动休眠」「待机亮度」会让设备立即重启**。

- 基线：`custom-final-20261027`
- 本版标签：`custom-final-20261027-r2`
- 源码：`e3fc53d`（修复在 `cd203c7`，文档在 `e3fc53d`）
- 构建：ESP-IDF 6.1，`media` 功能组合（english_dictation / stroke_order / web_file_transfer / music_player / chat_history 开，ble_keyboard 关）
- 固件：`media` 组合，**3,912,576 字节**（0x3bb380），app 分区余量 37.2%

## 一、现象

在设置页点这三行的 `+` / `−`，设备当场 `abort` 并复位；「待机省电」那一行却正常。
串口现场：

```
ESP_ERROR_CHECK failed: esp_err_t 0x1109 (ESP_ERR_NVS_KEY_TOO_LONG) at 0x4204b541
file: "./main/settings.cc" line 63
func: void Settings::SetInt(const std::string&, int32_t)
expression: nvs_set_i32(nvs_handle_, key.c_str(), value)

abort() was called at PC 0x403898ef on core 1
```

`0x1109` 就是 `ESP_ERR_NVS_KEY_TOO_LONG`。

## 二、根因

NVS 的 key 上限是 **15 个字符**（`NVS_KEY_NAME_MAX_SIZE - 1`，不含结尾 `\0`）。
三档省电那批代码用了描述性长名，全部越界：

| 设置项 | 原 key | 长度 | 结果 |
|---|---|---|---|
| 待机省电 | `idle_seconds` | 12 | 正常 |
| 深度省电 | `deep_save_seconds` | **17** | 写入 abort |
| 自动休眠 | `auto_sleep_seconds` | **18** | 写入 abort |
| 待机亮度 | `standby_brightness` | **18** | 写入 abort |
| 省电总开关 | `power_save_enabled` | **18** | 写入 abort |

`Settings::SetInt` 当时是 `ESP_ERROR_CHECK(nvs_set_i32(...))`，错误直接 abort。
`idle_seconds` 恰好 12 字符，所以那一行一直是好的 —— 这也解释了「为什么只有三行崩」。

**还有一个被掩盖的次生问题**：读取时 `nvs_get_i32` 同样返回 `KEY_TOO_LONG`，
但 `GetInt` 把这个错误当成「key 不存在」，直接返回默认值。所以启动日志里
`deep=3600s auto_sleep=14400s` 全程都是代码默认值 —— **这几项设置从来就没真正存进去过**，
即使不崩也不会生效。`power_save_enabled` 同理，开关永远读到 `true`。

## 三、修复

### 1. key 改短（真正的病根）

| 旧 key | 新 key | 长度 |
|---|---|---|
| `power_save_enabled` | `power_save_en` | 13 |
| `deep_save_seconds` | `deep_save_sec` | 13 |
| `auto_sleep_seconds` | `auto_sleep_sec` | 14 |
| `standby_brightness` | `standby_bright` | 14 |
| `power_save_display_off`（OLED 板） | `ps_display_off` | 14 |

`idle_seconds`（12）保持原名，已有取值不丢。其余几项因为从来没写成功过，
NVS 里本就不存在，**不需要迁移逻辑**。

全仓重新扫过一遍，最长的 key 现在是 `right_front_leg`（15，正好卡在上限内）。

### 2. `Settings` 不再用 `ESP_ERROR_CHECK`

一个设置项写失败不该把整机带进 panic。改动：

- `nvs_open` 检查返回值，失败时 `nvs_handle_` 保持 0，后续读写退化成默认值；
- `SetInt` / `SetString` / `SetBool` / `EraseKey` / `EraseAll` 全部改成手动判错 + `ESP_LOGE`；
- `nvs_commit` 失败只记日志；
- 入口统一校验 `key.size() > 15`，以后谁再写超长 key 只会打一条错误日志，不会再崩。

### 3. 调档立即生效（顺带修的功能缺陷）

`PowerSaveTimer` 的三个档位是构造时按值保存的，设置页只改了 NVS，运行中的实例并不知道，
所以调完档必须重启才生效。本版补上：

- `PowerSaveTimer::SetIntervals(sleep, deep, shutdown)`：运行时更新三档，并清掉
  `shutdown_requested_` 标记（否则「自动休眠」从关闭改成 4 小时会被旧标记直接跳过）；
- `Board::ApplyPowerSaveSettings()` 虚函数（基类空实现）；
- Freenove 板重写：读 NVS 新值推给定时器，若正停在档 1 则立即刷新待机亮度；
- 设置页 7 个回调在 `Settings` 析构（commit）之后调用它。

## 四、验证

同一台设备（COM4，`b8:1f:3f:c3:b6:c0`），逐项点 `+`/`−` 共 14 次：

```
PowerSaveTimer: Intervals updated: light=60s deep=3600s shutdown=14400s
PowerSaveTimer: Intervals updated: light=30s deep=3600s shutdown=14400s
PowerSaveTimer: Intervals updated: light=30s deep=7200s shutdown=14400s
PowerSaveTimer: Intervals updated: light=30s deep=7200s shutdown=28800s
PowerSaveTimer: Intervals updated: light=30s deep=7200s shutdown=14400s
```

- 14 次 `Power settings applied`，**0 次 abort / ESP_ERROR_CHECK**；
- 每次都有配对的 `Intervals updated`，证明热更新确实推到了运行中的实例；
- 重启后读回的是 NVS 真实值，不再是默认值。

## 五、升级方式

只写 app 分区，NVS / Wi-Fi 凭据 / 聊天记录 / 音乐索引全部保留：

```bash
python -m esptool --chip esp32s3 -p <PORT> -b 460800 \
  --before default-reset --after hard-reset write-flash 0x20000 build/xiaozhi.bin
```

## 七、遗留

- 旧的长 key 在 NVS 里从未写入成功，无需清理；但如果有设备曾用改主意前的中间版本
  跑过，可用 `nvs_tool` 确认 `power` 命名空间里没有 17/18 字符的残留项。
- `power_save_en` 开关关闭后再打开的路径本次未单独验证（日志里 14 次点击全为
  `enabled=1`），代码路径与档位调节一致，风险低。
