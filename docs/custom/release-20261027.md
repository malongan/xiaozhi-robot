# 2026-10-27 版本说明：三档待机省电 + 自动深度休眠 + 插电豁免

本版把「待机省电」从单一档位扩展成三档，并补上长时间无人使用的自动关机；
同时修掉一个「每关一次机音量就掉到 10」的老 bug。功能包组合沿用 r4 的 `media`。

- 基线：`custom-final-20261026-r4`
- 本版标签：`custom-final-20261027`
- 涉及提交：`40ca7b7`（三档省电）、`a332965`（插电豁免）、`164082f`（构建链路）

## 一、适用硬件与升级方式

- 板型：**Freenove ESP32-S3 Display 2.8"**（16 MB flash / 8 MB PSRAM，SD 4-bit SDMMC）
- 分区：沿用 `partitions/v2/16m_app6m.csv`，**本版不改分区**
- 升级（保留 NVS、Wi-Fi 凭据、聊天记录、音乐索引）：

```bash
python -m esptool --chip esp32s3 -p <PORT> -b 460800 \
  --before default-reset --after hard-reset write-flash 0x20000 build/xiaozhi.bin
```

- `xiaozhi.bin`（`media` 组合）：**3,910,800 字节**（0x3bac90），app 分区余量 37%

## 二、为什么要做成「三档」而不是「真休眠 + 语音唤醒」

需求原本是「1 小时无操作就进入长按 BOOT 那种休眠，但要能喊醒」。这两件事在
ESP32-S3 上**不能同时成立**，不是代码难度问题：

- `esp_deep_sleep_start()` 会停掉 CPU 与主域时钟，WakeNet 跑在 CPU 上，I2S 采音
  也要主域时钟，一旦睡下就没有任何东西在「听」；
- ULP-RISC-V 协处理器只有几十 KB 内存、几十 MHz，访问不到 I2S，跑不了唤醒模型。

所以最终做成三档，把「省电」和「可唤醒」的取舍交给用户：

| 档位 | 触发 | CPU | 背光 | Wi-Fi | 唤醒方式 | 电流（估算） |
|---|---|---|---|---|---|---|
| 活跃 | — | 240 MHz | 100% | 连接 | — | 150~200 mA |
| 档 1 省电 | 待机时长 | 40 MHz | 10% | 连接 | 语音 / 触摸 / BOOT | 50~70 mA |
| 档 2 深省电 | 深度省电时长 | 40 MHz | 0 | MAX_MODEM | **语音 / 触摸 / BOOT** | 25~40 mA |
| 深度休眠 | 自动休眠时长 | 停机 | 0 | 断开 | 仅 BOOT，冷启动 8~12 秒 | ~0.02 mA |

档 2 是「够省」与「喊得醒」共存的极限档：背光和 Wi-Fi 这两个耗电大头关掉，
麦克风与唤醒词照常工作。**实测在档 2 状态下喊「你好小智」能正常唤醒。**

## 三、设置页：三组档位

省电卡片从 3 行扩展到 5 行（高度 130 → 214，重启按钮下移到 y=504，页面可竖滚）：

| 设置项 | 可选档位 | 默认 |
|---|---|---|
| 待机省电（档 1） | 30 秒 / 1 / 5 / 10 / 30 分钟 | 1 分钟 |
| 深度省电（档 2） | 30 分钟 / 1 / 2 小时 | 1 小时 |
| 自动休眠 | 1 / 2 / 4 / 8 小时 / 关闭 | 4 小时 |

三档互相约束：改一档时会把冲突的相邻档推开，不会出现「深度省电比自动休眠还晚」
这种永远不会触发的配置。全部存 NVS `power` 命名空间：

```
power:idle_seconds       档 1 触发秒数
power:deep_save_seconds  档 2 触发秒数
power:auto_sleep_seconds 自动休眠秒数（0 = 关闭）
power:standby_brightness 档 1/2 的待机亮度
power:power_save_enabled 总开关
```

三个计时都从**最后一次交互**算起，喊一声、点一下屏幕都会清零，不会出现
「刚聊完五分钟就睡了」。

## 四、插着 USB 时不做档 2、不自动休眠

这条是必须的：自动休眠会让 USB-Serial/JTAG 跟着掉电，COM 口直接从系统里消失，
之后 esptool 连 `--before default-reset` 都进不去，只能物理按 BOOT 才能重新烧录。

- 插电时**档 1 仍然生效**（降频 + 背光 10%），只是不做档 2 和自动关机
- 档 2 期间插上电会立刻退出档 2，背光回到待机亮度，Wi-Fi 切回 MIN_MODEM
- 拔掉 USB 后计时清零重算，不会一拔线就黑屏
- **手动长按 BOOT 关机不受影响**，那是主动操作

检测方式：这台板没有 VBUS 回读（TP4054 的 CHRG 没引到 GPIO），只能分三层推断：

1. `usb_serial_jtag_is_connected()` —— 插在电脑上必定命中；
2. 没装电池 —— 只可能靠 USB 供电；
3. `FreenovePowerMonitor::IsCharging()` —— TP4054 正在从 USB 拉电流。

**已知边界**：插充电器、且电池已充满时三条都不命中（CHRG 没引出、电压也不再
上升），此时仍会进档 2。要彻底解决只能把 TP4054 的 CHRG 飞线到空闲 GPIO
（IO2/IO3/IO14/IO21），板级 `config.h` 里已经留好 `BATTERY_CHARGING_DETECT_PIN`。

## 五、修复：每关一次机，音量就掉到 10

原来 `PowerOff()` 用 `codec->SetOutputVolume(0)` 静音，而这个函数会把 0
**写进 NVS** 的 `audio/output_volume`；下次开机 `AudioCodec::Start()` 读到 0
就走「值太小」兜底改成 10。

现在关机时直接把下次开机的音量落 NVS（`kBootVolumeAfterPowerOff = 80`），
不经过 codec。原因：关机流程里唤醒词任务仍在 `ReadAudioData()`，发现麦克风被关
会立刻 `EnableInput(true)` 把 codec 重新打开（`dev_` 重建），此时 `SetOutputVolume`
就会真的推寄存器。写 NVS 语义明确，也不碰硬件。

实测 NVS 读出 `audio:output_volume = 80`，开机日志不再出现
`Output volume value (0) is too small, setting to default (10)`。

## 八、已知限制

- **自动休眠后必须按 BOOT 唤醒**，冷启动 8~12 秒，开机瞬间背光会全亮。
- 关机电流无法软件测量，`~0.02 mA` 是按 ESP32-S3 deep sleep 典型值推算；
  要实测需要 USB 电流计。
- MAX_MODEM 下 MQTT 长时保活只观察了 155 秒窗口，未验证整夜。若夜间频繁
  重连，说明 keepalive 需要调大。
- 插充电器且电池满电时插电豁免会失效，见第四节。
