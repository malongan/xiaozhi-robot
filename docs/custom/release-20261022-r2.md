# 2026-10-22 定制固件 r2 版本说明：内部 RAM 优化 + 启动提速 + 蓝牙运行时开关

本版是 2026-10-22 定制固件的第二个版本（r2），在原有功能之上解决"蓝牙常开时内部 RAM
只剩 15.6 KB、语音会话与新特性随时可能 OOM"的问题，并把启动到可交互的时间压缩近一半。

- 分支：`feat/bt-switch`
- 标签：`mem-opt-20261022`（文档与代码）、`custom-final-20261022-r2`（合并后的发布点）
- 详细复盘：[`lessons-20261022-memory.md`](lessons-20261022-memory.md)

## 一、适用硬件与升级方式

- 板型：**Freenove ESP32-S3 Display 2.8"**（16 MB flash / 8 MB PSRAM，SD 卡 4-bit SDMMC）
- 分区：沿用 `partitions/v2/16m_app6m.csv`（app 6 MB + assets 4 MB），**本版不改分区**
- 从上一版升级：只烧 app 到 `0x20000`，**保留 NVS、WiFi 凭据与蓝牙配对**：

```powershell
python -m esptool --chip esp32s3 -p COM4 -b 460800 write_flash `
  --flash_mode dio --flash_freq 80m --flash_size 16MB 0x20000 build\xiaozhi.bin
```

- 全新烧录（含 bootloader / 分区表 / assets）：

```powershell
python -m esptool --chip esp32s3 -p COM4 -b 460800 write_flash `
  --flash_mode dio --flash_freq 80m --flash_size 16MB `
  0x0 bootloader.bin 0x8000 partition-table.bin 0xd000 ota_data_initial.bin `
  0x20000 xiaozhi.bin 0xc00000 generated_assets.bin
```

- 发布文件：`bootloader.bin`、`partition-table.bin`、`ota_data_initial.bin`、
  `generated_assets.bin`、`xiaozhi.bin`、`CHECKSUMS.txt`
- `xiaozhi.bin` SHA256：`e43c06ce8f4cbd863361e51e9290c88d6cf557e2794e2a3d33f77ba030a87c02`
  （3,484,976 字节）

## 二、新增功能：设置页蓝牙开关

设置 → 连接卡片新增「蓝牙」开关（原「断开」按钮移除）：

| 状态 | 显示 |
| --- | --- |
| 已连接 | 已连接（绿 `#4CD964`） |
| 未连接 | 未连接（灰 `#939BAA`） |
| 已关闭 | 已关闭（暗 `#6D7585`），列表/空态/「清空」隐藏或置灰 |
| 切换中 | 正在开启… / 正在关闭…，开关置灰防连点 |

- 开关 = 广播开关：关 = 断开并释放协议栈，开 = 重新初始化并广播（已配对设备可直接重连）
- 状态持久化在 NVS（命名空间 `bluetooth`，键 `enabled`，默认开），重启后保持
- 「清空配对」保留，仅在蓝牙开启且未连接时可用
- 重启按钮由红色改为灰色，避免与"危险操作"混淆

## 三、内存与启动实测

| 指标 | 优化前 | 本版 |
| --- | --- | --- |
| 内部 RAM 空闲（蓝牙开） | 15,639 B | **~57–60 KB** |
| 内部 RAM 空闲（蓝牙关） | 78–82 KB | **~94 KB** |
| 蓝牙自身开销（内部 RAM） | ~66 KB | **37.8 KB**（另 27.5 KB 落 PSRAM） |
| 启动到 UI 可交互 | 3,788 ms | **1,795 ms** |
| 应用初始化完成 | 4,192 ms | **2,190 ms** |
| 静态 DIRAM | 178,379 B（52.19%） | 不变 |
| app 分区占用 | 3.32 MB / 5.94 MB | 不变（44% 余量） |

具体手段：

1. **蓝牙运行时反初始化**：`MediaBle::Stop()` → `nimble_port_stop()` +
   `nimble_port_deinit()`（含 controller disable/deinit）。实测关一次回收 62–66 KB。
   注意 `esp_bt_mem_release()` 在本芯片只回收约 1.3 KB 链接期 BSS，故未采用。
2. **NimBLE 内存外置**：`CONFIG_BT_NIMBLE_MEM_ALLOC_MODE_EXTERNAL=y`，host 池
   （msys/ACL/EVT/GATT cache，约 20–28 KB）进 PSRAM；controller 缓冲仍在内网。
3. **单连接**：`CONFIG_BT_NIMBLE_MAX_CONNECTIONS=1`（同时只连一个遥控器），省 5–8 KB。
4. **小额分配允许进 PSRAM**：`CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=256`（原 1024），
   空载多出 13–16 KB。
5. **笔顺 medians 懒加载**：`StrokeStore::Init()` 只读索引与拼音，1.61 MB 的
   `medians.bin` 首次进笔顺页才读。启动省 0.28 s，并让这部分 PSRAM 按需占用。
6. **英语音频自检后台化**：SD 上每次 `fopen` 约 85 ms，20 个文件原来在启动路径上占
   1.71 s；改为启动后 8 s 由 `eng_chk` 任务执行，且 `CheckAudio()` 改为只读 4 字节
   Ogg 头，不再整文件读入。

## 四、行为变化（升级需知）

1. 「断开」按钮取消，用开关代替；关闭蓝牙后，手机/遥控器需在设备重新开启后才能连接。
2. 蓝牙关闭状态会持久化：下次开机不会自动广播，需手动打开。
3. 笔顺页**首次**进入会出现短暂加载（约 0.3–0.5 s，读 1.6 MB），之后正常。
4. 启动日志里「音频自检：共 20 词，0 条异常」现在出现在开机约 10 s 后，属正常。
5. 蓝牙关闭瞬间可能打印一次
   `E MediaBle: adv set fields failed: 30`，是广播回调在协议栈下行时被触发，无害。

## 五、修复

- **蓝牙关掉后无法再打开**：`MediaBle::Start()` 初始化失败时未复位 `started_`，
  导致后续调用直接返回；现已复位。
- **开关任务导致重启**：切换任务最初使用 PSRAM 栈，BT 初始化短暂关闭 flash cache 时
  触发 `spi_flash_disable_interrupts_caches_and_other_cpu` 断言；已改为内部 RAM 栈
  （5,120 B，优先级 5）。
- **对话时栈溢出重启**（本版回归测试发现并已回滚）：曾把 `opus_codec` 栈由 24 KB
  降到 18 KB，空闲高水位"看起来够用"，但真实对话峰值超限 →
  `A stack overflow in task opus_codec` + `rst:0xc`。现已恢复 24 KB，
  `audio_input` 6 KB、`httpd` 8 KB/4 sockets 一并恢复。

## 六、已知问题

1. `E Dynamic Impl: mbedtls_ssl_fetch_input error=76` / `E esp-tls-mbedtls: read error :-0x004C`
   —— 历史上长期存在，与本版无关，不影响会话。
2. 蓝牙控制器 `libbtdm_app.a` 有 21,313 B 静态 DRAM，运行时无法回收；要省掉只能
   编译期 `CONFIG_BT_ENABLED=n`（会失去蓝牙遥控）。
3. 内部 RAM 最大连续块在蓝牙开启、WiFi 连接后约 25.6 KB，碎片化仍然存在；
   连续极端负载下的余量建议再观察。
4. 任务栈未做进一步瘦身：需要一次"完整对话后"的高水位数据才能安全评估。

## 七、验证记录（实机）

- 蓝牙开关连续多次 关→开：无重启，HID 遥控器可重连并正常输入
- 蓝牙开启 + 连续对话 5 分钟：串口无 OOM / 断言 / 重启
- 启动计时（临时诊断固件，INFO 级别 + 分段 mark）：
  SD 挂载 0.32 s、笔顺索引 0.22 s、词库 0.15 s、LCD 0.2 s、UI 布局 0.8 s、BLE 0.09 s
- 串口堆数据（切换开关时打印）：
  - 关：内部 57,223 → 96,855；PSRAM 2,483,776 → 2,512,156
  - 开：内部 91,887 → 54,115；PSRAM 2,023,436 → 1,995,920
- 主机侧测试：`python -m unittest discover -s scripts/tests` 98 通过，
  12 个 `FileNotFoundError` 为 Windows 环境缺少 `python3`/`cmake` 调用，与本次改动无关
