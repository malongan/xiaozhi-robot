## 二、功能包组合调整

### 本版组合：`media`

| 功能包 | 状态 |
|---|---|
| 音乐播放 | ✅ 开启 |
| 聊天记录 | ✅ 开启 |
| 英语听写 | ✅ 开启 |
| 笔顺 | ✅ 开启 |
| 网络文件传输 | ✅ 开启 |
| **蓝牙键盘** | ❌ **关闭** |

### 为什么关掉蓝牙键盘

实测蓝牙键盘是内部 RAM 的大户。三种组合对比（都是实机测得）：

| 指标 | 无音乐无键盘 | **仅音乐（本版）** | 音乐 + 键盘 |
|---|---|---|---|
| 稳态空闲 SRAM | 104.8 KB | **98.6 KB** | 36.9 KB 🚨 |
| 最低水位 | 33.4 KB | **33.4 KB** | 9.9 KB 🚨 |
| 最大连续块 | 43 KB | **36.9 KB** | 8.7 KB 🚨 |

原因很明确：**蓝牙控制器的实时缓冲必须留在内部 RAM**（BLE 时序要求微秒级响应，
PSRAM 延迟不满足），`BT_NIMBLE_MEM_ALLOC_MODE_EXTERNAL` 也救不了这部分，
光它就吃掉 68 KB。而音乐的任务栈（10 KB）和解码缓冲都能走 PSRAM，几乎不占内部 RAM。

`9.9 KB` 的最低水位在实际使用中会出问题：长回复重绘、音乐播放叠加对话时可能分配失败。

### 聊天记录的代价

| 指标 | 不开 | 开 |
|---|---|---|
| 空闲 SRAM | 99.1 KB | 98.6 KB |
| 最低水位 | 33.4 KB | 33.4 KB |
| 最大连续块 | 36.9 KB | 36.9 KB |

只占 0.5 KB 内部 RAM，可以忽略。卡上已有的 203 条记录完整保留。

## 三、修复：听写播几个词后停住

### 现象

先进行一段长对话，再进入听写，播放几个词后不再自动推进。

### 原因

`PlayCurrent()` 播放前会检查设备是否空闲：

```cpp
const bool server_busy = !app.GetAudioService().IsPlaybackIdle();
const bool state_busy  = 状态不是 idle/listing;
if (server_busy || state_busy) { 稍后重试; return false; }
```

`IsPlaybackIdle()` 要求解码队列空、播放队列空、解码不在进行、输出不在进行**四项同时满足**。
长时间对话后若某个标志残留，它会一直返回 false，于是每次都只是"稍后重试"，表现为卡死。

### 本版做法

1. **诊断日志**：重试时打出两个条件的值，便于定位是哪一边卡住

```
设备忙，稍后重试：star (server_busy=1 state_busy=0 state=4)
```

2. **10 秒超时兜底**：连续忙超过 10 秒就认为空闲判断不可信，直接放行播放

```
设备忙超过 10 秒（server_busy=1 state_busy=0 state=4），放行播放
```

这样即使判断失效也不会永久卡住，同时保留了日志用于后续根治。

## 四、修复：聊天记录标题与日期重叠

### 现象

标题居中、日期靠右，在 240 px 宽的屏幕上两者挨在一起。

### 本版做法

| 元素 | 改动 |
|---|---|
| 标题 | 居中 → 靠左（`x=52`，紧跟返回按钮） |
| 日期 | `2026-10-26` → **`26/10/26`**（年份两位，宽度约 110 px → 60 px） |
| 日期颜色 | `#8A90A0` → `#6E7484`，弱化，不抢标题 |

### 关于角色着色（试过，已撤销）

试过给「你」和「小智」用不同颜色（橙 / 青绿）区分说话人。两个方案都不合适：

| 方案 | 内存代价 | 结果 |
|---|---|---|
| LVGL recolor 富文本 | 0 | 折行会截断标记，出现「绿色里夹白字」 |
| 每条消息一个 label | **+21 KB 内部 RAM** | 颜色正确，但代价不划算 |

本版**回到单 label 方案，不做角色着色**，内存保持 98.6 KB。

## 五、其他改进

内存统计日志现在也会打 PSRAM 与最大连续块：

```
free sram: 98603 minimal sram: 33412 largest: 36864 | free psram: 3667320 minimal: ...
```

`largest`（最大连续块）比空闲总量更能提前发现碎片问题——它决定还能否分配大对象。

## 七、已知限制

- **听写卡住的根因未彻底定位**：本版是 10 秒超时兜底，治标。若复现，请提供
  `设备忙，稍后重试` 那行日志，可据 `server_busy` / `state_busy` 的值继续追查
- 聊天记录不分角色着色，读长记录时需要靠「你：」「小智：」文字区分
- 蓝牙键盘与音乐**不能同时开启**（内部 RAM 不足），如需键盘请用 `full` 以外的
  键盘组合，但要接受内存紧张
