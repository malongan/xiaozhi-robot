# 聊天记录（chat_history）

把每一轮对话追加写到 TF 卡，供离线回看。

## 为什么是可选功能包

存储层、回看页和防打断逻辑只在不插卡或不需要历史时才浪费 Flash 与内存。
默认关闭（`default n`），由 profile 或板级 `config.json` 打开。

## 数据结构

一天一个文件，路径 `/sdcard/chatlog/yyyymmdd.log`。

单条记录 = 24 字节定长头 + 变长 UTF-8 正文：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | seq，递增序号 |
| 4 | 4 | ts，Unix 时间戳（0 表示未知） |
| 8 | 1 | role，0=用户 1=助手 2=系统 |
| 9 | 1 | flags |
| 10 | 2 | 正文长度（小端） |
| 12 | 1 | magic `0xC7` |
| 13 | 3 | 保留 |
| 16 | 2 | CRC16/Modbus，正文校验 |
| 18 | 6 | 保留 |
| 24 | n | 正文 |

**定长头的作用**：回看翻页可以用 `fseek` 直接跳到第 N 条，不必顺序解析整天的文件。

## 容量与寿命控制

| 项 | 值 | 原因 |
|---|---|---|
| 单条正文上限 | 512 B | 屏幕只显示前几行，截断即可 |
| 单日文件上限 | 2 MB（约 4000 条） | 超过后轮转当天文件 |
| 保留天数 | 7 天 | 启动时清理超期文件 |
| 攒批刷盘 | 每 10 条或每 30 秒 | 减少 TF 卡写入次数，也不卡主循环 |

**断电安全**：只用 `fopen(..., "ab")` 追加写，不重写文件；每批写完 `fflush` + `fsync`。
断电最多丢掉最后一批（≤10 条）。

## 防打断（核心设计）

回看页打开期间必须做到"不出声、不被唤醒"，否则回看会被新一轮对话打断。
三层都要处理：

1. **关唤醒词**：`EnableWakeWordDetection(false)`，避免"你好小智"触发新会话。
2. **关语音处理**：`EnableVoiceProcessing(false)`，不开麦、不产生上行音频。
3. **丢弃下行 TTS**：服务器可能在回看期间推音频，必须在收包处**静默丢弃**而不是排队静音播放，
   否则退出回看后会一股脑播出来。

另有保险：回看 5 分钟无操作自动退出；退出后延迟 2 秒恢复唤醒词，避免用户还没松手就触发。

## 开关

```kconfig
config FEATURE_CHAT_HISTORY
    bool "Enable chat history on the TF card"
    default n
```

关闭时：不编译存储层、不创建回看页；抽屉第 7 格置灰并提示"聊天记录未启用"。
